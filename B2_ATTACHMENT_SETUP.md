# Zing Calendar v0.9.6.8 — B2 attachment transport

Structured records remain in the private GitHub data repository. Image/audio binaries now use the private Backblaze B2 bucket through short-lived presigned URLs generated by `/api/attachments` on Vercel.

Required Vercel Production environment variables:
- `B2_KEY_ID`
- `B2_APPLICATION_KEY`
- `B2_BUCKET_NAME=zing-calendar-attachments`
- `B2_ENDPOINT=s3.us-west-004.backblazeb2.com`

The B2 bucket must remain Private. The browser never receives the long-lived B2 key.

## Required B2 CORS rule
Before testing direct browser upload/download, configure the bucket CORS rule to allow the production origin `https://zing-calendar.vercel.app` with methods `GET`, `HEAD`, and `PUT`, and allow the `Content-Type` request header. Do not make the bucket public.

## One-time migration bridge
If a referenced attachment is absent from B2, sync first checks local IndexedDB. If local is absent, v0.9.6.8 reads the old immutable binary from the legacy GitHub `zing/attachments/` path, caches it locally, and uploads it to B2. New binary writes no longer go to GitHub.

Do not disable the old GitHub Pages entry until the Vercel origin has completed migration and images/audio have been verified.
