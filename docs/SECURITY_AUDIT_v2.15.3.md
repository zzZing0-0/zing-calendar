## 已修复

1. **IDB 替换异常可能提交清空或部分记录。** 同步 `put` 抛 DataError/DataCloneError 并不会自动撤销先前排队的 clear/put。统一显式 abort，写前验证主键唯一性。新增测试在修复前实际复现失败，修复后通过。
2. **读取失败被当作完成加载。** 原 catch 将 hydrated 置真，空 React 状态可反写清空持久化数据。失败不再开放对应持久化；新增笔记失败注入测试验证原记录和附件保留。未新增失败提示或重试交互。
3. **设置页自动附件清理存在竞态。** 打开设置仅统计；显式本地清理在同一事务重查持久化 owner 引用，保留回收站及重复任务例外引用。
4. **GitHub 写入失败前已应用远端修改。** 改为内存组合 → SHA 条件上传 → 收到成功后本地事务提交；409 重新读取两端。最终事务针对当前持久化状态合并，保留上传过程中新提交的本地编辑。现有冲突/预览确认机制保留，没有增加整包覆盖策略。
5. **远端输入和坏备份防护不足。** 拒绝非法同步实体/时间/标识/重复记录，备份先验证设置、数量、目录及引用字节完整性，UTF-8 解码失败明确拒绝，不先破坏本地数据。
6. **请求无客户端期限。** 同步和附件请求增加 30 秒 AbortSignal，保留调用方取消；不自动重放破坏性请求。
7. **版本多源不一致。** package 是唯一来源，脚本同步 lock，应用/页脚直接读取，生产 Worker 注入同一版本。
8. **生产离线缓存匹配失败。** 新测试实际复现带 `crossorigin` 的静态资源请求与预缓存 Origin 不同、`Vary: Origin` 导致离线白屏。仅当前缓存的带哈希 JS/CSS 忽略 Vary，API 仍不缓存。

## 未关闭风险与发布阻断

| 风险 | 已确认事实与限制 | 状态 |
| --- | --- | --- |
| B2 接口缺少代码内身份授权 | b2-sign 和 b2-gc 校验跨站头，但无 Origin 的非浏览器请求仍可进入；没有用户/会话授权检查。签名可允许 GET/HEAD/PUT，GC 使用服务端凭证删除。允许的键名不等于访问授权。 | 阻断。无法从本工作区确认线上 Vercel 是否有覆盖两端点的外层身份保护；已询问用户，不索取密钥。 |
| 陈旧客户端可能误删其他设备附件 | b2-gc 的 delete 重新列 bucket，但仍仅按客户端 referencedKeys 判定。没有获取权威 GitHub 引用集合，也没有跨设备引用一致性保障。 | 阻断。未对真实附件执行列举/清理/删除；不能宣称安全。 |
| PUT 未强制不可变 | “storageKey 不可变”是客户端约定，服务端签名没有强制写入不存在对象；结合授权缺口存在覆盖风险。 | 未排除，须随 B2 授权和写入约束一起处理。 |
| 实体写入与删除日志分事务 | App 的 save 与 recordSyncDiff 独立提交。进程在两者之间被终止时，删除标记可能漏记，远端旧记录可能复活。 | 阻断完整崩溃安全声明。需要以原子存储边界处理，不宜仅靠超时/内存标志声称解决。 |
| 完整恢复跨存储并非原子 | 主数据+附件在一个 IDB 事务；localStorage 设置及 userSettings 在之后写入。配额/中断可能留下新数据与旧设置，UI 旧状态仍可能反写。 | 阻断完整恢复失败保留旧状态的承诺。已增加坏输入提前拒绝，但未解决跨存储原子性。 |
| 恢复检查点有限 | 保存一个凭证无关的本地预合并结构包，不含二进制，不导出为完整备份，没有新增用户恢复按钮。本地显式清理不以该快照保留二进制。 | 不能称为完整、永久或自动回滚方案。 |
| 旧通用同步协议 | /api/sync/bundle 客户端保留，没有 GitHub SHA 条件写协议；当前 UI 使用 GitHub provider。 | 未验证真实服务，不得将其视作具有 GitHub 的并发保证。 |

没有通过临时关闭现有产品功能、删除冲突选择或更改数据结构掩盖上述问题。根据本次用户规定，存在未解决数据丢失风险不得自动发布，所以不得创建 v2.15.3 正式 Tag、推送 main 或触发部署。
