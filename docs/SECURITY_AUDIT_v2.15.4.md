## 三个阻断项的处理

1. **B2 身份认证/授权**：新增 `server/b2-authorization.ts`，两个端点统一调用。使用 Authorization Bearer 的现有设备 GitHub Token，服务端查询 `/user` 并验证数字用户 ID 允许列表，再验证固定私有数据仓库名称、数字 ID 和用户写权限。没有配置、凭据、身份匹配、权限，或上游失败/超时，都拒绝；不接受客户端声称的用户 ID，不依赖 Vercel Preview Protection，不将凭据送到 B2。没有永久缓存授权，拒绝重定向。**代码和 Mock 已验证，部署配置/真实身份集成尚未验证，仍阻断正式发布。**
2. **附件永久清理**：保留经授权的只读列表预览，删除请求在访问 bucket 之前返回 409。移除服务端 DELETE 实现，不能通过客户端 references/orphanKeys 或环境开关绕过。即使身份完全授权也不证明其他离线设备不再引用，所以不提供强制清理。预览候选不是可安全删除的证明。**永久误删路径已保守阻断，实际 B2 未执行操作。**
3. **事务边界**：新增 `saveEntityWithSync`，从同一事务的持久化记录计算 diff，将实体替换、tombstone 和 syncChanges 共同提交/撤销，重建时同时清除对应旧 tombstone。App 的 13 类实体通过共享 hook 调用；不再先 save 再逐条记录日志。恢复先准备设置、标签等，再将 13 类数据、附件及 userSettings 放进一个 IDB 事务。localStorage 是设置缓存，启动先从 IDB 重建后才挂载 React；投影失败时不挂载会反写旧状态的组件。没有 settings 行的旧安装仍读原 localStorage；旧备份格式、schema 12、协议 1 保持兼容。**故障注入、重开和实际恢复弹窗测试通过。**

其他相关修复：B2 PUT 绑定签名请求头 `If-None-Match: *`，浏览器必须发送此头；在未确认 provider 条件写支持前拒绝 PUT 签名，避免用 HEAD→PUT 的竞态假装不可变。笔记附件补入 B2 同步扫描，与任务、日记引用一起处理；原先笔记附件元数据可同步但扫描遗漏其二进制。

## 仍然存在的限制/未验证项

- 必需部署配置见 [B2 部署清单](B2_DEPLOYMENT.md)。本地无这些变量，无法读取/确认线上实际配置，不假设生产已有授权。不能推送 main 让正式部署首次试验访问控制。
- 未验证 B2 实际条件写支持、签名/CORS 兼容性；未验证时 PUT 禁止签名，已存在的本地附件/结构引用保留。未使用任何真实用户数据执行测试。
- 已签发 URL 保留其 300 秒有效窗口；Token 本地保存沿用既有风险模型，设备/XSS 攻陷不由本轮认证机制解决。
- 模拟事务中断、异常和 quota 注入不是物理断电试验。多标签页对同一记录的陈旧编辑、跨模块多个独立 UI 事务不是全局串行化；本轮解决每个实体与删除日志原子性以及完整恢复事务，不声称整个应用所有操作均为一个事务。
- 独立于当前 GitHub provider 的旧通用同步协议没有 SHA CAS；预合并恢复快照仍只有一份结构数据，不是二进制完整备份或恢复 UI。
- 浏览器验证为系统 Chromium 移动模拟，不代表真实 Safari/WebKit、真实 GitHub/B2/Vercel 集成已通过。

发布保持阻断，直到部署身份绑定、provider 条件写和隔离集成的实际证据齐备，不能把缺少配置导致的拒绝访问当作完整产品发布成功。
